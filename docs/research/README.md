# research/

## 役割

調べた結果を残す場所。決める前の調査に限らず、レビューや既存の文書・外部仕様の調査も含む。

## 他フォルダとの使い分け

- 症状から原因を追う調査は troubleshooting/ に置く。読む人の入口（症状）が違う
- 調査を踏まえて何かを選んだら、その決定は adr/ に書き、ここへリンクする

## 書き方のルール

- 調査日を必ず書く（JST、YYYY-MM-DD）。日付の無い調査結果は、古いのか新しいのか判断できない
- 出典を書く。一次情報と、二次情報や推測を区別する
- 事実と解釈を分けて書く
- 結論が出なかったことを書く。そこが次の調査の起点になる
- レビューの結果もここに残す。実施日・対象・実施者を必ず書く
  - 実施者はモデル名を書く（例: Opus 5.5）。人なら名前を書く
  - 同じ対象でもモデルによって指摘の質と量が変わるため、誰の指摘かが分からないと比べられない
- ファイル名は `YYYY-MM-DD-<主題>.md` とする。日付順に並び、同じ主題の調査を時系列で追える
- 1 ファイルの行数の目安は設けない。調査は分量が要る
- 理由を添える。理由の無い規約は守られないし、状況が変わっても見直されない
- 決まっていないことは「未確定」と明記する。埋めるために推測で書かない
