# prompt.md のレビュー

- 対象: prompt.md（コミット e8565ad 時点）

## 目的

初期プロンプトとして使ったときに、エージェントが迷う箇所や規約どうしの矛盾が無いかを確かめる。

## 事実（指摘。動作に影響するものから順に）

1. ADR の「承認後は書き換えない」と「古い方を置き換え済みにしてリンクする」が衝突していた。後者は古い ADR の書き換えにあたる
2. 「2 と 4 を先に作り、3 は後で README に書く」としつつ、4 は「作った規約を AGENTS.md にまとめる」となっており、4 の時点で何をまとめるかが不明だった。2 章の「個々の中身はまだ空でよい」も、README を指すのか各文書を指すのか読み取れなかった
3. タグを打ったら roadmap の該当項目にバージョンを書き添えるとしていたが、roadmap に完了項目の置き場が無かった
4. 最初のタグ（v0.1.0）をいつ打つかと、docs: などだけで区切りが完了した場合にタグをどうするかが書かれていなかった
5. 100 行ルールが AGENTS.md・roadmap に及ぶかが書かれていない
6. 表記の揺れ: 「Webサーバ」と「サーバー」、「そろえ」と「揃え」、「ユーザ」と「利用者」
7. 表がタブ区切りで、Markdown として表示すると表にならない

## 解釈

1〜4 は、エージェントが文字どおりに読むとどちらかの規約を破るか、推測で埋めることになる。5〜7 は動作への影響が小さい。

## 結論

1〜4 を修正した。

- 1: 承認済み ADR でも「状態」と「関連 ADR へのリンク」の欄だけは更新してよい、という例外を追加
- 2: 2 章で README に書く範囲を明示し、AGENTS.md はプロンプトの 3〜5 章を元にまとめると追記
- 3: docs/planning/archive/ を新設し、完了した項目を完了日・完了条件・タグと一緒に移す仕組みを追加
- 4: 最初のタグの条件と、上げる対象が無い区切りでは「タグなし」とすることを追加

続けて 5〜7 も修正した。

- 5: AGENTS.md と roadmap も 100 行以内を目安とし、超えたら AGENTS.md は詳細を docs/ に移してリンク、roadmap は archive/ への移し忘れを先に見る、とした。planning/archive/ は research/ と同じく例外とした
- 6: 「サーバー」「そろえる」に統一。「ユーザへの返答」は、本文の他の箇所が指示者を「私」と呼んでおり「利用者」とも意味が違うため、「私への返答」とした
- 7: 見出し・表・リストを Markdown の記法に直した。行の途中で折り返していた文は 1 行につなげた。記号と空白を除いた比較で、意図した変更以外に文言の差が無いことを確認した
