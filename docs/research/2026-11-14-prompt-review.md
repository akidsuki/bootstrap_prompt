## 結論

1〜16 を修正した。

- 1: 264 行を「1 章と 3〜5 章を元にまとめる」とした
- 2: 32〜35 行の「区切り」を「項目の完了」に言い換えた。タグを打たない条件は、26 行と同じく「前回のタグ以降のコミット」で書いた。「区切り」はコミットの時点の意味でだけ残る
- 3: 2 章の冒頭に git の準備（git init してよいかの確認、最初のコミットの前に .gitignore を作り秘密情報の規約を先に適用する）を置いた。既定ブランチ名と push・ブランチの運用は 1 章の未確定に加えた
- 4: 依頼者の判断で、見せるステップ自体を削除した。進め方は「2 と 4 を作り、続けて 3 を書き込む。コミットは 4 章の規約に従う」とした
- 5: 196 行を「バージョンによって AGENTS.md を自動では読まないため。CLAUDE.md から読み込めば、バージョンによらず読まれる」とした
- 6: 42 行に「planning/ の README には roadmap と archive/ の運用も書く」と例外を足した
- 7: 82 行に「.gitkeep を置く」と足した
- 8: adr/ に `NNNN-<題名>.md`（4 桁）、research/ に `YYYY-MM-DD-<主題>.md` を足した。識別子・ファイル名の言語と、形を決めていないフォルダの命名は 1 章の未確定に加えた
- 9: AGENTS.md では依頼者を「依頼者」と書くとした。README の「利用者」（このプロジェクトを使う人）と分けるため
- 10: README を正とし、README を変えたら AGENTS.md の要点も同じコミットで見直すとした
- 11: 利用者向けの詳細の置き場は未確定とし、移す時点で確認するとした
- 12: 「踏んだ落とし穴」には再開時の注意を短く書き、症状から原因を追った記録は troubleshooting/ に置いてリンクするとした
- 13: 「長いと要点が埋もれ、読まれなくなる」を理由として足した
- 14: 確認する対象が無い項目は「対象なし」と書くとした
- 15: 「対象（コードや文書）を読んで」とした
- 16: 文書の冒頭に「docs/ 配下は docs/ を省いて書く」と断り書きを足した

修正後、「区切り」がコミットの意味の 1 か所だけになったこと、表記の揺れ（「サーバ」「揃え」「ユーザ」）とタブ区切りが無いことを grep で確認した。
